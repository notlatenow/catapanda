# Catastrophic Pandamonium: Build Kit

Everything needed to build the Catastrophic Pandamonium (CataPanda) MVP from scratch in Lovable for **SheBuilds Season 04** (Lovable hackathon; category: Social Good: Civic Engagement; 15–17 October 2026). No code is included; the app is built entirely from these documents.

## What's in this folder

| File | What it is | Who it's for |
|---|---|---|
| `Catastrophic-Pandamonium-Project-Brief.docx` | The one-pager (about 3 pages): problem, solution, AI approach, scope, tech stack, timeline, risks | Judges, reviewers, anyone new to the project |
| `Catastrophic-Pandamonium-PRD.docx` | The full product requirements: every screen, list, rule, AI step and guardrail | The builder; the source of truth for how the product works |
| `Catastrophic-Pandamonium-Design-Guidelines.docx` | The visual system: brand, colors, stacked cards, buttons, item rows, imagery, what to avoid | Anyone designing or styling the app |
| `catapanda-checklist-data.md` | The vetted catalog: every item, note, priority, store type and source, plus tips and household rules | Upload to Lovable with prompt 1; edit here to update the catalog |
| `assets/web-logo.png` | The Catastrophic Pandamonium logo | Upload to Lovable with prompt 1 |
| `assets/web-mascots.png` | The cat and panda mascots | Upload to Lovable with prompt 1 |
| `prompts/` | Eight staged Lovable prompts plus a how-to README | Paste into Lovable one at a time |
| `submission-checklist.md` | The SheBuilds Hub form fields, with draft answers and screenshot suggestions | Use when submitting |

## How to use it

1. **Read the brief** for the big picture.
2. **Skim the PRD** so you know what "done" looks like. It's the reference whenever a question comes up during the build.
3. **Keep the design guidelines handy** for styling tweaks after the first build.
4. **Follow `prompts/00-README.md`**: set up the Lovable project, connect GitHub, then paste prompts 1–8 in order, testing each stage before the next.
5. **Submit with `submission-checklist.md`.**

## If something conflicts

The documents were written together and should agree. If they ever don't: the **PRD** wins for how the product works, the **design guidelines** win for how it looks, and **`catapanda-checklist-data.md`** wins for catalog content.
